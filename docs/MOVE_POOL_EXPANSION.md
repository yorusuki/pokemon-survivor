# 招式擴池與初始選擇比較

2026-10-19：2.3.0 已實裝 N01／N02，以下數據供後續機制討論，不另改抽選權重。

## 目前規則

| 項目 | 2.2.0 | 2.3.0 |
|---|---|---|
| 基礎招式／進化名稱 | 65／59 | 103／97 |
| 初始招式 | 預設固定 | 每隻寶可夢獨立花 400 寶可幣解鎖一次；之後免費更換 |
| 可選初始招式 | 預設招式 | 自身屬性＋一般池中的非增益招式；另保留原本初始招式，即使不同屬性 |
| 招式儲備 | 可開關，隨機第二招 | 同樣保留；第二招不重複初始招式、不選排除招式或增益招式 |
| 新招候選 | 最多 6 招，加權不重複抽選 | 不變，強項／無分類權重 2，弱項權重 1 |
| 最終升級畫面 | 候選再與已有招式強化、能力卡競爭 3 格 | 不變；新招卡權重 10、初期招式強化 8、一般能力卡 4；有進化時另有優先規則 |
| 排除／重抽 | 原永久強化上限 | 不變：排除最多 3 招，額外重抽最多 5 次，加每場免費 1 次 |

不是從全部 103 招等機率抽選；寶可夢的屬性、物特強弱、已學招式、排除項目、增益數量與欄位均會改變候選池。

## 固定早期狀態抽樣

以下以實際 LevelUp.offer 呼叫，各寶可夢各版本 20,000 次，隨機種子 71、LCG 更新式 `(1664525 × seed + 1013904223) mod 2^32`；候選及能力卡皆按程式抽樣。狀態固定為只有預設初始招式 Lv.1、無排除、無連結、未拿能力卡、4 欄尚有空位，每次顯示 3 張，不套初始招式選擇。只比較指定新招卡「出現在單次畫面」的頻率，沒有模擬整場升級、玩家選擇與進化。

| 寶可夢 | 可學池：前→後（含增益） | 觀察招式 | 前版出現率 | 新版出現率 |
|---|---|---|---|---|
| 妙蛙種子 | 17→23 | 飛葉快刀 | 8.82% | 6.03% |
| 皮卡丘 | 12→16 | 十萬伏特 | 12.90% | 9.03% |
| 可達鴨 | 14→17 | 水槍 | 16.36% | 13.41% |
| 噴火龍 | 18→23 | 噴射火焰 | 14.07% | 11.25% |
| 怪力 | 11→16 | 真空波 | 0.00% | 8.29% |

上述是抽樣估計，非精確機率；多數比例的 95% 抽樣誤差約 ±0.3～0.5 個百分點。真空波前版為 0%，因為當時不存在。各觀察招式不代表全部招式的平均值；不能由單一案例推論每招都降低相同比例。

## 解鎖初始招式後

若目標招式符合可選規則，解鎖後可直接以該招開場，這一點是確定取得，不需要用上述機率抽到。不能指定增益招式或任意異屬性招式；原本的異屬性初始招式是例外保留。初始招式 Lv.1，不會因此獲得進化或永久屬性加成。

兩個功能目前先按原作實裝。後續可討論：增加排除／重抽、特定招式偏好、分階段開放候選。這些均尚未實作；調整時應同時比較單屬性與雙屬性，避免縮池反而讓強勢組合更容易成形。

## 存檔、合併及安全

- 沿用 saves JSON，新增 `pstart[dex]={id,at}` 與 `pupg[dex].start`；不新增 SQL table／column。
- 購買費用依原作為 400；每隻寶可夢獨立，不是每帳號共用解鎖。
- 重新選回預設亦存實際 ID 及時間戳，合併取較新選擇，避免刪除欄位後被舊裝置復活；同時間戳以 ID 固定排序解決衝突。
- 選中的初始招式會從排除名單移除；開局亦避免舊合併資料排除初始招式。
- 伺服器驗證 ID 字串、dex、時間、欄位及存檔大小；客戶端額外確認擁有、已解鎖、招式存在且可選。這不等於伺服器權威反作弊。
- 2.3.0 API 與 web 一起更新、所有合作玩家重新載入；若回滾到 2.2.0，新選擇不生效。回滾前依既有方式備份資料庫。

## 單一屬性與生命寶珠

單一屬性寶可夢的同屬性招式另乘 1.2；其他屬性及雙屬性不套用。生命寶珠仍為傷害 ×1.3、最大生命 ×0.9、不扣攻擊反傷。符合條件時兩者乘積 1.56，寶珠本身沒有改值；再與其他物特、增益、相剋及天氣規則結算。
