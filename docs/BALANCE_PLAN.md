# 寶可夢生存平衡綜合方案

更新：2026-10-18。本文件整合目前決策，區分已實作與待確認方案。目標是讓喜愛不同寶可夢的玩家，在合理且相近的投入下都有可行流派，保留種族特色，而非把所有角色調成相同面板。

## 現況與原作的關係

來源與程式位置見 [原作參考與補強方向](POKEMON_BALANCE_DIRECTION.md)。本作取原作種族資料後換算：HP = round(70 + HP × 0.45)、移速 = round(78 + 速度 × 0.42)、攻擊 = round(0.70 + max(物攻, 特攻) × 0.0055, 2)。這不是原作實際能力公式；防禦、特防尚未對應成基礎耐久。速度由回合先後轉為即時走位，有些原作定位因此被削弱。

相剋關係參考原作，但運行倍率為 1.6／0.6／0.3，雙屬性限制 0.3～2.4；沒有完整的主系列 STAB 傷害公式。星級、能力卡、永久強化、治療者均有本作設計，不能以「原作如此」直接判斷平衡。

## 已實作：敵方支援第三版

[目前規則與風險](SUPPORT_BALANCE.md)採原作 e4ba0e1：治療依攻擊成長 7～17.5%，普通護盾35%，可自補，各類支援敵人上限3隻；頭目有近期輸出上限及補盾間隔。先前等級比例、共同間隔、25隻與開場60秒保護已停用。

## 待確認：保留特色的補強層

1. **先補齊資料缺口**：取得可追溯的防禦、特防資料，核對特殊型態與缺失值。先評估耐久換算；不把額外減傷疊到現有上限之外，避免無敵組合。
2. **依角色缺口補正**：比較清群、頭目、生存、走位與經驗效率，不只按星級發點。高雙防低攻速的角色，應能透過耐久或合適被動發揮定位；不能只因星級較高便失去補正資格。
3. **每帳號、每寶可夢培育**：建議提供有限且容易取得的補強額度，玩家可重配，用於該角色弱項；避免必須額外長期農資源才能接近一般角色。實際額度、上限、重置費用尚未核准，本次不實作。
4. **招式與屬性補盲**：檢查初始招式、可取得招式、近戰風險、軌道獨立冷卻和進化條件。必要時提供有限補盲選擇，不直接消除相剋；種族被動應可解釋且有上限。
5. **先修不一致，再調強度**：核對道具、臨時增益、永久強化與卡片的實際作用範圍。顯示資訊必須對應實際運算；錯誤修正與數值重平衡分別記錄。

先前按低星給 4／3／2／1／0 點、每點 2% 的 [技能點草案](POKEMON_TALENTS_PROPOSAL.md)，以及壓平種族面板、改相剋倍率的方向，均未套用。它們是歷史討論，不是此版本的平衡設定。護甲來源分離保留，防禦已改採原作80%效果上限、近戰及物特防禦另乘，詳見 [護甲修正](ARMOR_FIX_PROPOSAL.md)。

## 驗收矩陣與極端組合

| 比較軸 | 至少涵蓋 |
|---|---|
| 種族 | 低／高星、傳說、高雙防低攻速、低血高速、物攻／特攻偏科 |
| 投入 | 零、中、滿永久強化；相同投入比較，不用不同養成掩蓋差距 |
| 流派 | 近戰、遠程、範圍、軌道、持續傷害、增益；缺少有效攻擊的組合 |
| 環境 | 單人、四人；有利／不利相剋、雙屬性極值、天氣、液體地形 |
| 疊加 | 減傷上限與近戰減傷、攻擊乘算、冷卻與獨立命中間隔、回血與最大生命、移速與拾取、祭壇／道具／增益 |
| 敵方 | 開場、密集群怪、支援重疊、頭目、30 分鐘以上 |

固定版本與隨機種子重複比較擊殺時間、每分鐘經驗、頭目擊殺時間、承傷、死亡率與 30 分鐘成功率；合作額外看房主與訪客結果一致性。目標容許區間須在取得基準後另行確認，不能只看單局通關就宣稱公平。尤其避免高減傷加回血、極低冷卻加範圍、合作共享經驗等組合抵銷所有代價。

## 分階段與資料流程

- **階段 A（目前）**：限制敵方支援、提供能力可見性；不改種族與相剋。文件整理不會自動啟用後續方案。
- **階段 B（待確認）**：補齊種族資料、建立測試基準，提出具體耐久換算與補強表，再決定套用。
- **階段 C（待確認）**：加入帳號／寶可夢培育；先確定存檔版本、點數來源、總額與重配，再實作伺服器驗證及介面。
- **階段 D（待確認）**：灰度測試與極端組合回歸，最後評估是否需區分排行榜規則版本。

目前不新增資料表或 SQL migration。未來培育可先評估既有 saves JSON，但分配點數不能沿用逐屬性取最大值的合併，否則跨裝置重配會憑空增點。須由伺服器按總預算驗證，在交易與 revision 衝突控制下整體更新；舊存檔保留原永久強化與貨幣，不自動轉換或扣除。若需新增 schema，另行取得確認並安排備份與遷移。

每個已驗證階段使用獨立 Git commit，必要時 git revert。涉及資料轉換時，程式回滾不等於資料回滾，必須先設計向後相容與資料還原。實際容器、四人跨網路與長局實戰仍需部署端驗收。
