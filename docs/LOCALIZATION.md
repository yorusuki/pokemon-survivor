# 繁體中文名稱與翻譯

## 資料來源與可靠性

寶可夢、招式、道具名稱使用 [PokéAPI 官方資料庫 repository](https://github.com/PokeAPI/pokeapi/tree/master/data/v2/csv)的多語 CSV，以語言 ID 4（zh-Hant）取得繁中名稱。

寶可夢依全國圖鑑編號比對；招式與道具先以遊戲現有英文對照名稱做正規化精確比對，不使用模糊搜尋猜測。比對失敗會停止產生，不默默填入機翻名稱。

目前遊戲目錄的覆蓋率為寶可夢 966/966、基本招式 103/103、進化招式名稱 97/97、道具 11/11。詳細原文、英文、繁中、資料 ID、下載 URL 及 SHA-256 見 [terminology-zh-TW.json](terminology-zh-TW.json)。進化招式中的「Enjambre／Swarm」是原作借用特性名稱的自訂招式，因此依特性 CSV 譯為「蟲之預感」，報告有另行註記，並未把它冒稱為主系列官方招式。

PokéAPI 是社群維護資料庫，不是寶可夢官方命名的逐筆認證服務。已以[台灣寶可夢官方圖鑑的妙蛙種子頁面](https://tw.portal-pokemon.com/pokedex/0001/)抽查名稱；不能把這項抽查宣稱為全部 966 筆官方核驗。若未來資料庫與官方新譯名不同，應以官方公告為準並記錄修正來源。

一般文案根據原文及實際遊戲程式重譯，涵蓋性格測驗、設定、招式描述、戰鬥提示、任務、成就、社交、更新紀錄與繁中內容頁。固定名稱仍採資料庫對照；遊戲自訂效果不代表寶可夢主系列原始招式效果。這不是專業譯者或使用者逐句驗收的宣稱。

## 實作

- `js/data/lang-zh-TW.js`：產生的詞典及以 ID 對照的名稱。
- `js/core/i18n.js`：支援 `zh-TW`，繁中瀏覽器自動選用；玩家選擇存於 `ps.lang`，切換時重新整理。
- `js/core/localized-data.js`：依 ID 套用寶可夢、招式、道具名稱；不更改存檔 ID。例如西文「Psíquico」同時表示屬性與招式，屬性翻為「超能力」，招式 ID `psychic` 則顯示「精神強念」。
- `zh-TW/`：繁中入口與 10 個內容頁。主攻略模板在 `tools/templates/guide-zh-TW.html`。
- 預設採 Cubic 11，保留平滑字型選項及系統 CJK fallback；DOM 與 Canvas 均有繁中支援。

## 重建

需要 Node.js 22、Python 3.10 以上。中文化工具只使用 Python 標準函式庫，不需要 Pillow。

```sh
node tools/export_data.js
python tools/localize_zh_tw.py
node tools/build.js --plain --sin-seo
```

首次執行只會下載 PokéAPI 名稱 CSV，不會將介面或玩家資料送往翻譯服務。一般文案只讀取專案內的兩份校訂詞典：

- `tools/translations/zh-TW.json`：以完整原文為鍵的語境譯文。
- `tools/translations/zh-TW-context.json`：性格名稱、操作用語與西文同字異義的明確對照。

「run」依情境譯為一場冒險或遊玩場次；「move」在操作中為移動，在技能中為招式；「boss」為頭目。全螢幕的離開按鈕、帳號登出、空房位與不指定招式等情境使用不同原文鍵，避免套用錯誤詞義。

工具會檢查現有介面、靜態頁文字與可見屬性是否有譯文，並檢查 `{x}` 參數數量。缺少內容時寫入 `tools/cache/missing-zh-TW.json` 並停止，不會自動填入機翻。參數的語意與順序另由測試案例檢查。

`tools/cache/` 只保存名稱來源與中間產物；產生流程不再讀取舊機翻快取。修改譯文請編輯上述 JSON，而不是直接改 `js/data/lang-zh-TW.js`。修改後重新執行匯出、中文化與建置指令。

原始英文／西文頁仍由既有 `make_seo_pages.py` 維護；若重新產生，需補上新增文字的校訂譯文，再重新產生中文頁與遊戲 bundle。

## 動態排行榜與暱稱流程校訂（2026-10-17）

詞典產生工具的 coverage 只表示已匯出的來源有譯文，不等於所有動態 UI 均已驗證。排行榜原本只為英文組合個人名次句子，繁中誤落入西文分支；已補上繁中完整句子及期間情境（今日／本週／本月／歷史總榜），不將 Diario 一律改譯而影響其他「冒險筆記」情境。

暱稱頁先前修改了說明，完整詞典鍵未同步；現以兩個完整段落維護對應來源。排行榜新紀錄提示、等級／擊敗數也依目前語言顯示。玩家暱稱保留原文並保持 HTML escaping，不把玩家輸入交給翻譯。

`server/tests/localization.test.js` 新增讀取 dev.html 真實暱稱段落，以及載入真正 RankingUI 的輸出回歸，覆蓋期間／單人合作／空榜／未進前 50／名次／寶可夢篩選／錯誤訊息／玩家名稱與列資料。這輪未對 部署版本本執行瀏覽器驗收；同步新版專案並重建 web 才會更新 bundle。

## 非英文暱稱核實（2026-10-17）

目前規則是 Unicode Letter／Number／底線、3～16 個字元；不只接受英文。透過真正 HTTP API 與 PGlite 測試下列名稱，確認註冊／登入、名稱保留與公開 profile、名稱查詢、存檔、房間成員與排行榜摘要可往返保留原文：小火龍訓練家、ピカチュウ、포켓몬친구、ТренерПикачу、Éclair_123、مدرببوكيمون、โปเกมอน。這是資料流程驗證，不是 瀏覽器全部字型／語向的視覺驗收。

已知限制（本次檢查未更改名稱或認證規則）：

- 2 字名稱（例如小智）、空格、連字號、其他標點、Emoji 不符合規則。
- Unicode Mark 不在允許清單內，因此含組合附加符號的文字會被拒絕。例如預組合 é 可接受，e 加 U+0301 不可；部分帶附標的泰文、阿拉伯文等也不符合。
- 沒有統一 Unicode normalization。土耳其大寫 İ 轉小寫會包含 U+0307；原名稱可通過驗證／註冊，但暱稱鍵與路徑驗證會拒絕。
- 前端 regex 的長度以 Unicode code point 計算，profile／排行榜等部分限制與 HTML maxlength 使用 UTF-16 code units。補充平面漢字如𠮷占兩個 UTF-16 units；9 個𠮷會通過 regex，但 profile 保存失敗（介面也可能先限制輸入）。一般常用中文不受此差異影響。

新增 `server/tests/unicode-names.test.js` 記錄正常往返與這些已知邊界；失敗的暱稱交易不留下半份 reservation／profile。上述規則不代表全面支援所有語言，不能以名稱使用非英文一概判斷成功或失敗。
